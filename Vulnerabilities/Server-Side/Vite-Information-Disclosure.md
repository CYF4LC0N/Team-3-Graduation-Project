# Information Disclosure via Exposed Vite Development Server

## Summary

An **Information Disclosure / Security Misconfiguration** vulnerability exists due to the Vite development server being accessible from outside the application's intended network boundary on TCP port **5173**.

Unlike a production deployment, where only files within the web root are exposed, the Vite development server serves static files from the project root directory by default. As a result, an unauthenticated remote user can directly retrieve files located in the project root that are not explicitly protected by Vite's internal deny-list.

During testing, the files `composer.lock` and `output.txt` were successfully retrieved without authentication. Although files such as `.env` were protected by Vite's default deny configuration, the server follows a deny-list approach rather than an explicit allow-list, meaning additional project-root files may also be exposed.

## Affected Endpoint

```http
http://localhost:5173/
```

---

## Impact

An unauthenticated attacker can access files exposed by the Vite development server without interacting with the Laravel application.

Successful exploitation may result in:

- Disclosure of project configuration files.
- Exposure of dependency information (`composer.lock`).
- Disclosure of development or debugging artifacts.
- Collection of information useful for further attacks.
- Increased attack surface due to unintended exposure of the project directory.

---

## Steps to Reproduce

1. Access the Vite development server:

```http
GET http://localhost:5173/
```

2. Request a file located in the project root, for example:

```http
GET /composer.lock
```

3. Observe that the file is returned successfully.

4. Request another project-root file:

```http
GET /output.txt
```

5. Observe that the file is also publicly accessible.

6. Attempt to retrieve `.env`.

7. Observe that access is denied due to Vite's built-in deny-list, indicating that only selected filenames are blocked while other project files remain accessible.


---

## Root Cause

The Vite development server is exposed to untrusted networks and serves files directly from the project root directory.

Its security model relies on a deny-list of sensitive filenames instead of restricting access to an explicit public directory, allowing project-root files that are not explicitly denied to be downloaded by unauthenticated users.

---

## Remediation

- Do not expose the Vite development server outside local development environments.
- Bind the development server to `localhost` or disable it entirely outside developer workstations.
- In staging and production environments, serve only the compiled frontend assets generated by `npm run build`.
- Restrict access to development services using firewall rules, VPN access, or authenticated reverse proxies.
- Adopt a secure-by-default configuration that serves content only from an explicitly intended public directory.
- Remove development artifacts (such as `output.txt`) from deployment packages and version control where appropriate.
- Regularly audit exposed development services to ensure they are not reachable from untrusted networks.
